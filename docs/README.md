## The docs site

`/newspapper/docs/` is a Docusaurus site built from this folder. Almost all of it is rendered from the project wiki: `scripts/sync-corpus.mjs` renders every `corpus/wiki/` page, plus `corpus/log.md`, into `docs/wiki/` (gitignored) on every build. It discovers the pages rather than reading a list, so a new wiki page is published without anyone remembering to add it; a page kept back on purpose goes in the script's `DENY` set, which is empty. TypeDoc writes the `@newspapper/core` reference into `static/reference/`, and `diagrams/pipeline.json` compiles to `static/diagrams/pipeline.html` through archify when it is installed (the HTML is committed, so the build works without it). The one page written by hand is `docs/index.mdx`. Edit the corpus, never `docs/wiki/`.

```bash
npm run docs --workspace=docs    # sync, diagrams, TypeDoc, then docusaurus build into docs/dist/
npm run typecheck --workspace=docs
```

The base path is set in `docusaurus.config.ts` (`DOCS_BASE` overrides it), the sidebar in `sidebars.ts`, and The Mechanical theme in `src/css/custom.css`. A synced page that is not in `sidebars.ts` is built and linked but not listed, so add new wiki pages there. vps-deploy publishes `docs/dist/` to `/newspapper/docs/` together with the app. It does not build the site, so run the command above first. To preview, serve `docs/dist/` under `/newspapper/docs/` with any plain static server; `docusaurus serve` breaks the hashed font URLs and search on this site's trailing-slash routes.

The package has no `"type": "module"`, unlike the app's three workspaces, because Docusaurus's build fails with it ([why](../corpus/wiki/decisions-tooling.md#the-docs-workspace-is-the-one-package-without-type-module)).
