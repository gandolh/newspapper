**Newspapper** turns a story into an Instagram-style slide post: a set of
1080×1080 JPEGs plus a caption, ready to upload.

You write the post yourself, as a **Newspapper Wizard** (`.wzd`) document, in a
split-screen editor — source on one side, the live 1080 canvas on the other. The
app compiles it and screenshots each slide in headless Chromium.

```
.wzd document  →  compile  →  HTML  →  Chromium  →  1080² JPEGs  →  publish / ZIP
```

## This site is almost entirely rendered, on purpose

Newspapper's corpus already carries [`api.md`](/wiki/api/), [`data.md`](/wiki/data/),
[`architecture.md`](/wiki/architecture/), [`modules.md`](/wiki/modules/),
[`configuration.md`](/wiki/configuration/), [`commands.md`](/wiki/commands/) and
[`markup.md`](/wiki/markup/) — twenty-four maintained pages in all, including the
reference material a docs site would normally author for itself.

Restating any of it here would create a second copy to keep in step with the
first, and the second copy always loses. So **this page is the only authored one**;
everything else in the sidebar is rendered from `corpus/` on every build and
carries a banner saying so, or is generated by TypeDoc from `@newspapper/core`.

## The one thing worth reading first

[**Green because nothing ran**](/wiki/green-because-nothing-ran/).

It is the page that says which parts of this system have actually been executed
and which have only ever type-checked. A test suite that is green because it
never reached the code is the failure mode this project chose to write down
rather than discover later, and it is the honest starting point for anyone
picking the repo up.

## The security premise changed

Newspapper was designed for **loopback, single-user** — and every one of its
security calls said so explicitly, including the note that the assumption was the
first thing to revisit if it were ever exposed.

That moment arrived: it is going to the VPS, on the shared origin, behind Ward.
Three of its original calls met real internet traffic — a public `/uploads/*`, a
non-revocable 30-day cookie, and an IP-keyed lockout.

The `/uploads/*` exposure was closed by **intercepting the request rather than
authorising it**: the render context already served fonts from disk, so the same
mechanism removes the image request instead of granting it a credential. No new
bearer token exists — no lifetime, no signing key, no leak path, no revocation
story.

See [decisions-security.md](/wiki/decisions-security/).
